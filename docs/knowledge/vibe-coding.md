# 用 AI 做 Vibe Coding 的正确姿势

你好久没写代码，**不要**一上来让 AI「把整个平台生成完」。

正确节奏：

> **你定边界 → AI 写切片 → 你跑起来验证 → 你理解关键路径**

---

## 1. 每次对话给 AI 的最小上下文

1. 当前目标（例如：「只做场地草稿创建 API」）
2. 对应需求编号（如 `VEN-001`）
3. 相关文档路径
4. 明确边界（「不要动支付」「不要新建微服务」）
5. 验收方式（「本地能 migrate + curl 通」）

---

## 2. 推荐提示词模板

```text
我们在做 IVBA（见 docs/）。当前阶段是 Stage X / Phase X。
请只做：……
约束：遵循 docs/TECH_STACK.md；不要引入新技术；不要做范围外功能。
完成后请：
1) 列出改了哪些文件
2) 告诉我如何本地验证
3) 指出我应该复习的 2–3 个知识点
```

---

## 3. 你必须亲自盯住的点

AI 容易写得「看起来对、实际上危险」：

- 权限：组织成员角色、管理员二次授权
- 钱与库存：金额服务端重算、锁库存、幂等键
- webhook：验签、事件 ID 唯一、重复投递
- 时段冲突：数据库 exclusion constraint，不只靠应用层 if
- 隐私：日志不落 token/卡号；生产数据不进本地

---

## 4. 每天学习节奏（建议）

| 时长 | 做什么 |
| --- | --- |
| 30–45 分钟 | 复习一个基础主题（TS / SQL / Go / HTTP） |
| 60–90 分钟 | 和 AI 一起完成一个很小的纵向切片 |
| 15 分钟 | 写到 [notes.md](./notes.md) |

---

## 5. 复制给 AI 的下一步指令

1. `按 docs/SETUP.md 帮我把 Docker 和本地 Postgres/PostGIS 跑起来`
2. `按 TECH_STACK 初始化 monorepo 脚手架（Web/Expo/Go/OpenAPI/Makefile），先不要写业务`
3. `帮我画核心 ERD 和场地申请状态机草案，落到 docs/`
4. `做第一个 OpenAPI vertical slice：已登录用户创建场地草稿`
