# 产品需求规格（MVP）

## 1. 目的与优先级

本文将产品目标转为可设计、可开发和可验收的需求。需求优先级：

- **P0**：MVP 上线闭环必需；
- **P1**：MVP 稳定后优先加入；
- **P2**：远期能力，不应影响首版架构。

需求编号将用于 ERD、OpenAPI、页面、GitHub Issues 和测试用例追踪。

## 2. 权限模型

| 能力 | 访客 | 普通用户 | 主办 Staff | 主办 Owner | 场地 Staff | 场地 Owner | 平台 Admin |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 浏览公开场地/活动 | 是 | 是 | 是 | 是 | 是 | 是 | 是 |
| 购票/管理个人订单 | 否 | 是 | 是 | 是 | 是 | 是 | 是（支持） |
| 创建场地租用申请 | 否 | 否 | 是 | 是 | 否 | 视组织而定 | 是（支持） |
| 管理本组织活动 | 否 | 否 | 是 | 是 | 否 | 视组织而定 | 是（支持） |
| 管理本组织场地 | 否 | 否 | 否 | 视组织而定 | 是 | 是 | 是（支持） |
| 管理组织成员/付款 | 否 | 否 | 否 | 是 | 否 | 是 | 受限支持 |
| 审核/封禁/全局退款 | 否 | 否 | 否 | 否 | 否 | 否 | 是 |

最终权限不按“用户全局类型”判断，而按用户对资源所属组织的 membership 和 role 判断。

## 3. 身份与账户

### P0

- **AUTH-001** 用户可以通过邮箱注册、验证邮箱、登录和退出。
- **AUTH-002** 用户可以发起忘记密码并安全重置密码。
- **AUTH-003** Website 和 App 可以保持会话，并在 access token 过期时安全刷新。
- **AUTH-004** 用户可以查看和修改姓名、头像、联系电话及必要偏好。
- **AUTH-005** 用户可以请求账号停用、数据导出和删除。
- **AUTH-006** 系统必须记录服务条款与隐私政策的接受版本和时间。
- **AUTH-007** 敏感 token 必须存储在平台安全存储中，不能明文持久化。

### P1

- **AUTH-101** 支持 Google 和 Apple 登录。
- **AUTH-102** 组织 Owner 和平台 Admin 支持/强制 MFA。
- **AUTH-103** 用户可以查看并撤销其他设备会话。

## 4. 组织与成员

### P0

- **ORG-001** 已登录用户可以创建主办组织或场地组织。
- **ORG-002** 组织包含法定/展示名称、简介、联系方式、地址、验证状态和付款状态。
- **ORG-003** Owner 可以通过邮箱邀请成员，并授予 Owner 或 Staff 权限。
- **ORG-004** 被邀请者可以接受或拒绝邀请。
- **ORG-005** Owner 可以移除成员；系统必须确保组织始终至少保留一个 Owner。
- **ORG-006** 所有成员、角色和付款设置变更必须写入审计日志。
- **ORG-007** 一名用户可以属于多个组织并切换当前工作上下文。

### P1

- **ORG-101** 增加更细权限，例如 venue manager、event manager、finance viewer。
- **ORG-102** 支持管理员要求组织补充验证材料。

## 5. 场地和空间

### P0

- **VEN-001** 场地方可以创建、编辑、预览和归档场地。
- **VEN-002** 场地包含名称、简介、完整地址、位置、交通、无障碍信息、政策和联系方式。
- **VEN-003** 一个场地可以包含多个可单独租用的空间。
- **VEN-004** 空间包含容量、布局、面积、价格指引、设施、允许/禁止活动类型和图片。
- **VEN-005** 场地方可以排序、替换和删除媒体，并设置封面图。
- **VEN-006** 草稿只有本组织成员和管理员可见；已发布内容才允许公众访问。
- **VEN-007** 新场地或关键资料变更可以提交审核，管理员可批准、退回修改或拒绝。
- **VEN-008** 公开用户可以按地点、距离、容量、价格范围、设施和无障碍条件筛选。
- **VEN-009** 场地详情必须显示价格是固定价格、起价还是需询价，不能误导用户。

### P1

- **VEN-101** 场地方可以保存重复可用性规则和临时例外。
- **VEN-102** 支持 iCal/Google/Outlook 日历只读同步。
- **VEN-103** 支持场地验证徽章和资料完整度。

## 6. 场地租用申请

### P0

- **HIRE-001** 主办方可以从指定空间发起租用申请。
- **HIRE-002** 申请包含期望日期/时间、进退场时间、预计人数、活动类型、需求说明和联系组织。
- **HIRE-003** 提交前系统必须检查必填字段，但不得将“看似可用”误表示为最终确认。
- **HIRE-004** 场地方可以查看本组织申请列表和详情。
- **HIRE-005** 场地方可以接受、拒绝、要求修改或发送带有效期的报价。
- **HIRE-006** 主办方可以接受或拒绝报价。
- **HIRE-007** 已确认租用不得与同空间其他已确认租用发生时间重叠。
- **HIRE-008** 双方可以在申请内发送结构化消息，记录发送人和时间。
- **HIRE-009** 所有状态变化必须有操作者、原因和时间记录。
- **HIRE-010** 双方可以取消；系统根据已确认政策计算可退款状态，实际退款由支付流程处理。
- **HIRE-011** 申请、报价、确认、拒绝和取消必须触发站内/邮件通知。

### 建议状态

```text
draft → submitted → under_review → quoted → accepted → payment_pending → confirmed
                    ↘ changes_requested
                    ↘ rejected
quoted/accepted/payment_pending/confirmed → cancelled
```

具体状态转换和可操作方必须在状态机 ADR 中最终确认。

### P1

- **HIRE-101** 支持订金、尾款和到期提醒。
- **HIRE-102** 支持报价版本和附加费用明细。
- **HIRE-103** 对标准化空间启用即时预订。

## 7. 活动、场次和票种

### P0

- **EVT-001** 主办方可以创建、编辑、预览、复制和归档活动。
- **EVT-002** 活动包含标题、描述、分类、图片、年龄限制、无障碍信息、退款说明和联系人。
- **EVT-003** 活动可以关联平台内已确认租用，也可以由管理员允许使用外部场地地址。
- **EVT-004** 一个活动可以有一个或多个场次。
- **EVT-005** 场次包含开始/结束时间、时区、销售起止时间和总容量。
- **EVT-006** 每个场次可以设置多个票种，包括名称、说明、价格、数量、每单限购和销售时间。
- **EVT-007** 主办方可保存草稿并提交审核。
- **EVT-008** 管理员可以批准、退回修改、拒绝、取消发布或暂停销售。
- **EVT-009** 只有已批准且处于销售/展示时间范围内的活动对公众可见。
- **EVT-010** 已产生订单后，对时间、地点、年龄限制等关键字段的修改必须受到限制并触发用户通知。

### P1

- **EVT-101** 等候名单。
- **EVT-102** 折扣码、邀请票和赠票。
- **EVT-103** 重复活动批量生成场次。

## 8. 发现、搜索和收藏

### P0

- **DISC-001** 访客和用户可以浏览即将开始的已发布活动。
- **DISC-002** 可以按关键词、地点/距离、日期、分类、价格和年龄限制筛选活动。
- **DISC-003** 搜索结果必须支持稳定分页和无结果状态。
- **DISC-004** 活动详情显示主办方、场地、场次、价格、剩余状态、退款规则和无障碍信息。
- **DISC-005** 用户可以收藏/取消收藏活动，并查看收藏列表。
- **DISC-006** 已取消、售罄和结束的活动必须明确显示状态，不能继续普通购票。

### P1

- **DISC-101** 基于地点、分类和近期行为的可解释推荐。
- **DISC-102** 保存搜索条件和新活动提醒。

## 9. 购物车、订单和库存

### P0

- **ORD-001** 用户选择场次、票种和数量后，系统创建有明确过期时间的库存锁。
- **ORD-002** 并发请求不得导致票种或场次超卖。
- **ORD-003** 一个订单记录买方、货币、项目金额、费用、折扣、税额（如适用）和总额快照。
- **ORD-004** 价格和政策必须在服务器端重新计算，不能信任客户端金额。
- **ORD-005** 库存锁到期或付款失败后自动释放。
- **ORD-006** 用户可以查看订单列表和订单详情。
- **ORD-007** 订单必须区分 pending、paid、cancelled、partially_refunded、refunded 和 payment_failed。
- **ORD-008** 创建订单必须支持幂等键，避免重复点击产生重复订单。
- **ORD-009** 免费票也必须创建订单和票券，但不进入 Stripe 支付。

## 10. 支付、退款和结算

### P0

- **PAY-001** 付费订单通过 Stripe 支付，不处理或存储完整银行卡数据。
- **PAY-002** Stripe webhook 是最终付款状态来源，客户端成功页面不能直接将订单标记 paid。
- **PAY-003** webhook 必须验证签名、记录 provider event ID 并幂等处理。
- **PAY-004** 支付失败、需要额外验证和成功状态必须正确反馈给用户。
- **PAY-005** 管理员可以在授权和审计范围内发起全额或部分退款。
- **PAY-006** 用户和主办方可以查看退款状态和金额。
- **PAY-007** 平台费用、支付费用和向 connected account 的金额必须单独记录。
- **PAY-008** 未完成 Stripe/KYC onboarding 的组织不得接收需要结算的付款。
- **PAY-009** 退款、拒付和 webhook 异常必须进入运营处理队列。

Stripe Connect 模式和 Merchant of Record 未确认前，本节不代表最终资金流。

### P1

- **PAY-101** 场地租用的订金和尾款。
- **PAY-102** 自动化 payout 状态与对账导出。
- **PAY-103** 商业组织订阅。

## 11. 电子票和核销

### P0

- **TKT-001** 订单确认后，每个参与名额签发一个唯一票券。
- **TKT-002** 票券包含不可预测、可验证的 QR token，不能直接暴露连续数据库 ID。
- **TKT-003** 用户可以在 App 和 Website 查看票券；必要时可通过邮件获得入口。
- **TKT-004** 被授权的主办成员可以扫描并核销票券。
- **TKT-005** 重复扫描必须显示已核销时间和核销设备/成员，不得再次成功。
- **TKT-006** 已退款、取消、作废或属于其他场次的票券不得核销。
- **TKT-007** 每次扫描尝试必须记录结果用于审计和故障排查。

### P1

- **TKT-101** 有限时间离线核销与安全同步。
- **TKT-102** 票券转让或重新分配参与者。
- **TKT-103** Apple Wallet/Google Wallet。

## 12. 通知

### P0

- **NOT-001** 关键交易通知同时支持站内和邮件；App 可使用 push 提醒。
- **NOT-002** 用户可以管理非必要通知偏好，但不能关闭付款、取消和安全等必要服务通知。
- **NOT-003** 通知任务必须重试并记录最终失败，不得阻塞核心交易事务。
- **NOT-004** 通知内容不得包含敏感付款或身份数据。
- **NOT-005** 重要链接必须 deep link 到相应订单、申请或票券。

### P1

- **NOT-101** 活动开始提醒和收藏活动变化提醒。
- **NOT-102** 保存搜索的新活动提醒。

## 13. 管理员与平台运营

### P0

- **ADM-001** 管理员可以搜索和查看用户、组织、场地、活动、申请、订单和付款。
- **ADM-002** 管理员可以审核场地、活动和组织验证资料。
- **ADM-003** 管理员可以暂停内容、组织或用户，并填写原因。
- **ADM-004** 管理员可以查看付款/webhook/通知失败队列。
- **ADM-005** 管理员可以在权限允许时处理退款和票券作废。
- **ADM-006** 高风险操作必须二次确认并写入不可由普通管理员修改的审计日志。
- **ADM-007** 支持人员默认只看到处理事件所需的最小个人数据。
- **ADM-008** 管理后台显示场地、活动、申请、订单、GMV、退款和核销的基础指标。

### P1

- **ADM-101** 管理员分级权限和审批工作流。
- **ADM-102** 举报、纠纷和客服 case 管理。
- **ADM-103** 聚合数据导出。

## 14. 隐私与合规

### P0

- **PRIV-001** 系统维护数据处理目的、保留期限和第三方处理商清单。
- **PRIV-002** 营销 consent 必须独立、可撤回并记录版本/时间。
- **PRIV-003** 非必要分析和 cookie 在有效 consent 前不得启用。
- **PRIV-004** 用户可以发起数据访问、导出、更正和删除请求。
- **PRIV-005** 删除请求需要处理订单/税务/审计的法定保留例外，而非盲目物理删除全部记录。
- **PRIV-006** participant 信息仅在活动确实需要时收集。
- **PRIV-007** 如果允许面向儿童的服务，必须在上线前完成相应 DPIA 和年龄适宜设计评估。
- **PRIV-008** 生产数据不得复制到本地或普通预览环境。

## 15. 非功能需求

以下目标需在容量和预算确认后最终签署。

### 安全

- **NFR-SEC-001** 全部外部流量使用 TLS；敏感 secrets 使用 secret manager。
- **NFR-SEC-002** 服务端对所有输入、授权和金额重新验证。
- **NFR-SEC-003** 登录、搜索、下单、上传和扫描接口实行适当 rate limit。
- **NFR-SEC-004** 图片上传限制 MIME、大小、所有者和 signed URL 有效期。
- **NFR-SEC-005** 日志不得包含密码、token、银行卡或完整敏感表单。
- **NFR-SEC-006** 依赖与容器镜像持续扫描；严重漏洞阻止生产发布。

### 可靠性和一致性

- **NFR-REL-001** 超卖和同空间重叠确认必须通过数据库事务/约束防止。
- **NFR-REL-002** webhook、订单创建、退款和后台任务必须幂等。
- **NFR-REL-003** 数据库必须有自动备份、PITR 和定期恢复演练。
- **NFR-REL-004** 第三方服务失败不得导致已完成交易丢失；通过 outbox 重试后续任务。

### 性能建议目标

- **NFR-PERF-001** 正常负载下，常用读取 API p95 目标小于 500ms（不含第三方调用）。
- **NFR-PERF-002** 搜索必须分页并使用 PostGIS/数据库索引。
- **NFR-PERF-003** 公共 Web 核心页面移动端 LCP 目标小于 2.5 秒。
- **NFR-PERF-004** 图片使用响应式尺寸、压缩和 CDN。

### 可访问性和兼容性

- **NFR-A11Y-001** Website 目标达到 WCAG 2.2 AA。
- **NFR-A11Y-002** App 支持系统字体缩放、屏幕阅读器标签和足够触控区域。
- **NFR-A11Y-003** 颜色不能作为传达状态的唯一方式。
- **NFR-COMP-001** 明确支持最近两个主流 iOS/Android 大版本和现代 evergreen browsers，具体版本在发布策略中记录。

### 可观测性

- **NFR-OBS-001** 每个 API 请求带 request ID，并可关联订单、job 和 webhook 日志。
- **NFR-OBS-002** 付款失败、库存异常、worker backlog 和高错误率必须告警。
- **NFR-OBS-003** 错误监控必须移除或屏蔽个人敏感数据。

## 16. MVP 验收场景

MVP 完成必须至少通过以下端到端场景：

1. 场地 Owner 创建组织、场地和空间，管理员批准后公众可搜索；
2. 主办 Owner 创建组织并提交租用申请，场地方报价，主办方接受后形成无冲突确认；
3. 主办方创建活动、场次和票种，管理员批准后公开；
4. 两个用户并发购买最后一张票，只能有一个成功；
5. 用户付款后，即使 success page 重复打开或 webhook 重复到达，也只产生一套订单票券；
6. 用户在 App 查看 QR 票，主办方成功核销一次，第二次显示重复扫描；
7. 管理员执行退款后，订单、退款、票券和审计状态一致；
8. 未授权用户无法读取或修改其他组织的非公开数据；
9. 邮件/推送临时失败不回滚已经完成的订单，并能稍后重试；
10. 用户能够提交数据导出/删除请求并由运营人员跟踪处理。

## 17. 分析事件基线

MVP 至少定义以下事件，并避免携带不必要个人数据：

- `venue_search_performed`, `venue_viewed`, `hire_request_started/submitted`；
- `hire_quote_sent/accepted`, `hire_confirmed/cancelled`；
- `event_search_performed`, `event_viewed`, `ticket_checkout_started`；
- `payment_succeeded/failed`, `order_refunded`；
- `ticket_viewed/scanned`, `scan_rejected`；
- `venue_published`, `event_published`, `review_completed`。

## 18. 尚未确定的问题

1. 首发城市、目标活动类别和初始供给；
2. 场地租用的最终状态机和报价有效期；
3. 门票库存锁定时长、每单限购和免费票规则；
4. 平台收费、Merchant of Record 和资金流；
5. 退款、取消、改期、拒付和 no-show 责任；
6. 活动与场地审核标准及 SLA；
7. 是否收集参与者姓名/年龄，是否允许儿童活动；
8. 客服、退款、纠纷和线下安全事件的负责人；
9. MVP 是否包含场地租用付款，还是仅申请与人工确认；
10. 发布时承诺的性能、可用性、RPO 和 RTO。
