# 实施路线图

路线图以可演示、可验证的纵向业务切片为单位，而不是先把所有页面画完或先把全部后端搭完。

## Phase 0：产品与法律确认（1–2 周）

- 与 Artspace Lifespace 确认用户、商业模式和首发城市；
- 确认 Merchant of Record、平台收费、退款和取消政策；
- 画出两条交易链及全部状态；
- 完成信息架构、低保真流程和基础品牌方向；
- 创建数据地图、DPIA 初筛和供应商清单；
- 定义 MVP 验收标准和分析事件。

退出条件：产品负责人签字确认范围；未决问题不会改变数据库核心模型或支付责任。

## Phase 1：工程基础（约 1 周）

- 初始化 pnpm/Turborepo；
- 创建 Next.js、Expo 应用和 Go 模块化单体 API；
- 建立 OpenAPI → oapi-codegen 与 OpenAPI → RTK Query codegen；
- 配置 TypeScript、lint、格式化、测试和 CI；
- 建立本地/预览/生产环境策略；
- 建立 pgx/sqlc、数据库迁移、seed 和集成测试流程；
- 加入错误监控但禁止敏感数据上报。

退出条件：Web、App 和 Go API 可在 CI 构建并通过基础测试；数据库可从零迁移和 seed；预览部署可访问。

## Phase 2：身份、组织与场地目录（2–3 周）

- 登录、会话、个人资料；
- 组织与成员角色；
- 场地、空间、图片与位置；
- 公共场地列表/详情及筛选；
- Go 授权策略、数据库约束、管理员审核和审计日志。

退出条件：场地方可创建草稿，管理员可审核发布，公众只能看到已发布内容。

## Phase 3：场地租用流程（2–3 周）

- 可用性规则与例外；
- 主办方租用申请、报价/消息、接受/拒绝；
- 冲突检测和状态历史；
- 邮件通知；
- 根据已确认商业规则加入订金/付款。

退出条件：一笔场地申请可从创建完整走到确认或拒绝，且不会产生重复确认时段。

## Phase 4：活动与票务 Web 闭环（3–4 周）

- 活动、场次、票种和发布审核；
- 搜索与活动详情；
- 库存锁定、Checkout、webhook、订单和退款基础流程；
- 电子票与二维码；
- 管理后台订单列表和核销接口。

退出条件：测试用户可以完成一次真实测试支付并获得唯一有效票券；重复 webhook 不会重复出票。

## Phase 5：App（3–4 周）

- 复用领域契约和 API；
- 活动发现、筛选与详情；
- 登录、Checkout 跳转/支付、订单与票券；
- 推送通知；
- Maestro 核心流程和 EAS 内测构建。

退出条件：iOS/Android 内测用户可完成浏览、购买、查看票券的核心路径。

## Phase 6：上线准备（2 周）

- Playwright/Maestro 回归与无障碍测试；
- 支付失败、退款、取消、超卖和 webhook 故障演练；
- 数据导出/删除流程与保留策略验证；
- 监控、告警、备份恢复和运营 runbook；
- App Store/Play Store 材料、隐私标签与生产发布。

## 首个开发里程碑

第一段代码不应从首页开始。建议首个纵向切片是：

> 场地方创建场地草稿 → 管理员审核 → 场地出现在公开 Web 搜索 → 主办方提交租用申请。

这个切片会尽早验证身份、组织权限、数据模型、图片、位置、审核与通知，是后续所有功能的基础。
